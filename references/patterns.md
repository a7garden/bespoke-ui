# 과업별 구조와 조작 예시

**데이터의 모양에서 직접 안을 지은 뒤, 막혔을 때만 본다.** 먼저 보면 어느 화면에서나 같은 답이 나와 이 목록이 새 습관이 된다.
예시의 이름과 모양을 그대로 쓰지 않는다. 이 과업의 판단 · 데이터 · 제품 얼굴에 맞게 비틀어 쓴다.
각 예시는 「대체한 기본안 → 새 형태 → 왜 나은가」 순서다.

## 업무 · 운영 화면

**기한 띠 (RiskFuse)**
상태 배지 + 마감일 글자 → 접수부터 기한까지 가로 띠, 지난 만큼 채움 · 남은 날이 적으면 끝이 굵어짐 · 단계 눈금.
목록을 훑기만 해도 「누가 급한가」가 모양으로 보인다.

**단계 레일 (StageRail)**
1 · 2 · 3 스텝퍼 → 단계 폭이 걸린 날수에 비례하는 레일. 막힌 단계는 레일이 끊겨 보인다.
「어디서 오래 걸렸나」가 질문인 화면에 맞다.

**지금 선 레인 (NowLane)**
날짜 칸 정렬 표 → 가운데 「지금」 세로선, 왼쪽은 지난 일 · 오른쪽은 다가올 일. 건마다 한 줄.
오늘 할 일과 이미 늦은 일이 선 하나로 갈린다.

**처리량 흐름 (FlowStrip)**
KPI 타일 네 개(접수 · 검토 중 · 회신 · 반려) → 왼쪽에서 오른쪽으로 흐르는 띠 하나, 갈래마다 폭 = 건수.
숫자끼리 이어진 흐름이 보이고 어디서 새는지 드러난다.

**선택한 행과 판단 근거**
예외 목록에서 수량과 사유는 행에 남기고, 자세한 근거가 필요한 행을 선택하면 옆 영역이 그 행을 따라간다. 목록의 선택과 스크롤을 그대로 보존한다. 상세가 짧다면 행에 바로 배치하고, 좁은 화면에서 근거가 길다면 이름이 있는 상세로 연다.

## 데이터 · 판단 화면

**범위 막대 (RangeBar)**
예측값 숫자 하나 → 낮음 · 가능성 높은 구간 · 높음을 한 막대에, 기준선(경보 기준)을 겹쳐.
「기준을 넘을 수도 있나」가 숫자보다 먼저 읽힌다.

**비교 렌즈 (DiffLens)**
이전 · 이번 두 탭 → 한 화면에 겹치고 가운데 손잡이를 밀어 전후를 본다. 바뀐 칸만 밝힌다.
중간 위치가 판단에 필요하면 손잡이를 끌지 않고도 클릭·탭과 키보드로 그 위치에 갈 수 있게 한다. 양 끝만 비교하면 충분할 때는 ‘이전·이후’ 버튼으로 비교한다.

**위험도 축 정렬 (RiskAxis)**
같은 크기 카드 그리드 → 가로축이 위험도, 점 크기가 영향 범위. 맨 오른쪽 위가 먼저 볼 것.

**스파크라인 행 (SparkRow)**
지역별 카드 12장 → 한 줄에 이름 · 7일 추세선 · 지금 값 · 기준 대비 차이. 12줄이 한 화면에 들어온다.
추세가 판단 근거일 때만 쓴다. 추세선에는 기준선을 겹치고 지금 값을 글자로 같이 둔다. 빈자리 채우기용이면 지운다.

## 대화 · AI 화면

**근거 붙은 답 (CitedAnswer)**
말풍선 → 답 문장마다 작은 근거 표식, 누르면 원문 조각이 옆에 펼쳐짐. 믿을지 말지를 그 자리에서 판단한다.

**다음 동작 칩 (NextMoves)**
「더 궁금한 점이 있으신가요?」 → 지금 답에서 이어지는 실제 동작 2~3개(지도에서 보기 · 보고서 열기 · 기준 바꿔 다시 묻기).

**생각 중 줄 (WorkTrace)**
빙글 도는 표시 → 지금 무엇을 찾고 있는지 한 줄씩 쌓이는 진행 줄. 기다리는 이유가 보인다.

## 입력 · 설정 화면

입력해야 할 값부터 세기 전에 **값을 어디에서 판단하고 결과를 어디에서 확인하는지** 그린다. 같은 필드라도 수정 빈도와 적용 범위에 따라 자리가 달라진다.

| 과업 | 화면과 조작 | 반영과 복구 |
| - | - | - |
| 공개 범위 몇 가지 중 하나 선택 | 현재 범위와 차이를 직접 읽을 수 있게 선택지를 나란히 놓는다. | 선택과 공개 확정이 다른 행동이면 구분하고 대상·범위를 확정 행동 가까이 둔다. |
| 수백 개 거래처 중 한 곳 선택 | 입력을 시작하면 검색 결과와 식별 정보가 같은 자리에서 나타난다. 선택 뒤에도 거래처 이름과 식별 정보를 남긴다. | 잘못 골랐을 때 같은 자리에서 바꾼다. 입력 오류 뒤에도 다른 값은 보존한다. |
| 주문 한 건의 메모 수정 | 읽는 자리에서 해당 문장만 입력으로 전환한다. | 변경 상태를 문장 옆에서 확인하고, 실패하면 입력을 유지한 채 재시도한다. |
| 여러 품목의 실사 수량 입력 | 같은 단위를 가진 품목을 표에서 읽고 같은 열에서 위아래로 이동해 입력한다. 재고 차이를 행마다 보여준다. | 임시 입력과 재고 반영을 구분한다. 반영 전 바뀌는 품목과 수량을 확인하고 오류는 해당 행에 표시한다. |
| 기존 자료를 바탕으로 신규 작업 등록 | 출처에서 이미 얻은 값은 확인·수정할 수 있게 보여주고, 첫 결정을 하는 데 빠진 값부터 묻는다. | 조건부 입력은 앞 선택 뒤에 나타난다. 중단 후 다시 열 때 초안과 적용 대상을 알아볼 수 있게 한다. |

**값을 끌어서 (DragValue)**
결과가 연속으로 바뀌는 수치라면 끌면서 결과를 미리 본다. 정확한 값 입력·키보드 조작도 같은 자리에서 제공한다.

**결과 먼저 설정 (PreviewFirst)**
설정 목록 → 위에 결과 미리보기, 아래 설정을 바꾸면 미리보기가 즉시 따라옴. 설정의 뜻을 결과로 배운다.

**빈 상태 = 첫 동작 (EmptyAction)**
일러스트 + 「데이터가 없습니다」 → 그 자리에 첫 건을 만드는 입력 한 줄, 또는 무엇이 있어야 채워지는지 조건 한 줄.

## 배치

### 같은 과업의 뼈대를 바꿔 보기

예를 들어 과업이 **다른 주문을 건드리지 않고, 재고가 모자란 주문을 찾아 가능한 조치를 한다**라면 아래 세 형태는 출발점과 판단 순서가 다르다.

| 구조 | 첫 화면과 첫 행동 | 판단·확정·복구 |
| - | - | - |
| **예외 목록에서 시작** | 조치가 필요한 주문이 먼저 보인다. 주문을 고르면 부족 품목, 수량, 가용 재고가 옆에 나타난다. | 건별 조치 후 다음 주문으로 이어진다. 실패하면 선택한 주문과 입력이 남는다. 반복 처리에 맞는다. |
| **하나의 주문에서 시작** | 주문 메시지나 링크가 해당 주문의 출고 상세를 연다. 출고 예정 수량과 실제 가능 수량을 품목별로 견준다. | 부족한 품목 옆에서 조치하고 주문의 변경 결과를 그 화면에서 확인한다. 특정 건을 깊게 처리할 때 맞는다. |
| **같은 SKU를 중심으로 시작** | 한 품목의 가용 재고와 그 재고를 기다리는 주문을 함께 보고 무엇을 먼저 배정할지 결정한다. | 바뀌는 주문과 수량을 확정 전에 요약한다. 같은 재고를 놓고 여러 주문이 경쟁할 때 맞는다. |

세 안은 각각 주문 간 전환, 특정 주문의 근거 보존, 여러 주문에 걸친 배정에 유리하다. 현재 과업에서 어느 비용이 더 큰지 고르고, 좁은 화면에서도 같은 근거를 보고 같은 결정에 도달할 수 있는지 확인한다.

### 배치의 재료

**주인공이 화면을 가진다 (HeroCanvas)**
헤더 + KPI 네 칸 + 카드 그리드 → 주인공(지도 · 타임라인 · 목록) 하나가 화면 대부분, 건수 · 필터 · 동작은 그 가장자리에 얇게 붙는다.
눈이 처음 닿는 곳이 판단할 곳이다.

**축이 바탕인 화면 (AxisStage)**
날짜 칸이 있는 표 → 화면 가로 전체가 시간축, 건은 그 위의 줄. 필터는 축 머리에, 한 건의 근거는 축과 함께 보이는 영역에 둔다.
「언제」를 읽으려고 글자를 해석할 필요가 없다.

**지도 위에 뜨는 판 (FloatingPanes)**
왼쪽 목록 + 오른쪽 지도 반반 → 지도가 화면 전체 바탕, 목록과 상세는 지도 위에 뜬 불투명한 판으로 한쪽 가장자리에. 판을 접으면 지도만 남는다.
공간이 주인공인 화면에서 지도 폭을 반으로 깎지 않는다.

**목록 옆 상세 (SplitFocus)**
목록 → 상세 화면 이동 → 목록 폭을 줄여 왼쪽에 남기고 오른쪽에 상세. 위아래 키로 건을 넘기며 상세가 따라 바뀐다.
여러 건을 차례로 처리하는 일에서 「뒤로 → 다음 건 → 열기」를 없앤다.

**필터를 데이터에 (InlineFilter)**
왼쪽 필터 패널 → 열 머리 · 축 머리를 누르면 그 자리에서 거르기. 걸린 조건은 목록 머리에 꼬리표로 한 줄.
필터 패널이 차지하던 폭을 데이터에 돌려준다.

**비대칭 두 단 (WeightedSplit)**
같은 폭 두 단 → 7 : 3 처럼 한쪽에 무게. 넓은 쪽이 판단, 좁은 쪽이 그 판단의 근거나 동작.
두 단이 같은 폭이면 무엇이 먼저인지 화면이 말해 주지 않는다.
