# 시각 디자인과 마감

화면의 첫인상과 판단 순서가 같은 곳을 가리키게 한다. 사용자가 가치를 얻는 실제 내용에 시각적 밀도를 주고, 그 주변의 조작은 차분하고 정확하게 다듬는다.

## 제품에 맞는 방향을 고른다

있는 제품은 인접 화면의 글꼴·색·간격·이미지·컴포넌트를 확인한다. 변경 범위에서 이미 쓸 수 있는 토큰과 자산을 찾는다. 새 화면의 스타일을 정할 수 있다면 실제 화면 내용 한 조각을 골라 작은 시안을 비교한다. 제품이 어떤 순간에 쓰이고 무엇이 먼저 보여야 하는지를 바탕으로 결정을 내린다.

- **시각적 중심을 실제 내용에서 찾는다.** 시간표에서는 공통 시간축과 공연명의 리듬, 편집 도구에서는 원본과 결과, 작품 소개에서는 실제 작품과 캡션의 관계가 화면의 개성이 될 수 있다. 선택한 중심이 타이포, 간격, 비례, 이미지 편집, 상태 표시 중 어느 부분을 바꾸는지 적는다.
- **구체적인 결정을 남긴다.** 예를 들어 차분한 현장 도구라면 줄 정렬, 비교 가능한 숫자, 위험 신호의 제한된 색으로 구현한다. 활기 있는 공개 프로그램이라면 큰 시간, 다른 폭의 프로그램 영역, 실제 작품 사진으로 리듬을 준다. 서로 다른 제품에서 이름만 바꿔도 성립하는 시안이라면 실제 내용과 판단 방식에서 구성을 다시 시작한다.
- **막연한 스타일 형용사를 형태로 바꾼다.** 제목의 크기와 굵기, 반복 행의 기준선, 한 가지 강조색이 쓰이는 위치, 배경과 내용의 대비를 실제 내용으로 정한다. 토큰이 없는 제품이라면 이 선택을 몇 가지 재사용 가능한 역할과 간격으로 정리한다. 밝은 테마와 어두운 테마를 함께 지원하는 제품에서는 역할이 두 테마에서 같은 의미를 내는지 본다.
- **시각 자산에는 역할을 준다.** 제품, 장소, 기록을 알아봐야 하면 제공되거나 사용 가능한 실제 자산을 쓴다. 이미지가 읽기나 선택에 도움이 되거나 브리프의 분위기를 만들 때 공간과 크롭을 정한다. 필요한 자산이나 데이터가 없으면 실제로 있는 내용과 정상적인 빈 상태를 중심으로 그린다. 샘플이 실제 운영 정보처럼 보일 수 있으면 샘플임을 알린다.

## 문구를 화면에서 다듬는다

- 실제 제목·긴 이름·숫자·단위·조건을 넣고 읽는 순서부터 맞춘다. 페이지 제목과 줄마다 반복되는 설명, 장식용 배지, 성과 문구는 그 자리에서 새로운 정보를 주는지 확인한다. 필요한 레이블과 조건은 짧게 유지한다.
- 같은 대상을 같은 이름으로 부른다. 버튼에는 완료할 일을 쓴다. 동의, 발송, 권한 변경처럼 결과가 중요한 조작은 영향을 받는 대상과 결과를 그 가까이에 둔다.
- 빈 검색 결과, 첫 사용, 권한 없음, 로딩, 실패는 알려진 사실에 따라 문구를 정한다. 불러오지 못한 데이터를 0으로 표시하면 의미가 달라진다. 잘못된 값은 해당 입력에서 고칠 수 있게 하고, 서버 실패에는 유효한 입력과 선택을 보존한다. 근거 있는 재시도·다시 열기·지원 경로만 보여준다.

## 구현할 시각 결정을 내린다

| 영역 | 정할 것 |
| - | - |
| 타이포그래피 | 제목·본문·보조·조작·수치를 구분한다. 언어와 글자 길이에 맞춰 행간과 폭을 조정하고, 비교할 숫자는 단위·정렬·자리 폭을 맞춘다. 전시용 크기는 내용 자체가 중심일 때 쓴다. |
| 간격과 배치 | 같은 의미의 행은 기준선을 공유한다. 한 묶음 안의 간격과 묶음 사이의 차이가 보이게 한다. 큰 빈 공간은 작품이나 핵심 내용에 집중할 때 쓰고, 첫 행동을 밀어낸다면 줄인다. |
| 색과 표면 | 바탕·본문·보조·행동·선택·상태에 일관된 역할을 준다. 강조색의 면적도 위계다. 표면을 분리할 필요가 있을 때 간격, 엷은 경계, 깊이 중 필요한 수단을 고른다. 그림자·그라데이션·유리 효과·큰 모서리의 쓰임을 설명할 수 있어야 한다. |
| 조작과 상태 | 읽기, 선택, 편집, 반영됨이 서로 다르게 보이게 한다. 아이콘은 뜻이 선명하거나 이름이 함께 있을 때 쓴다. 조작의 접근 가능한 이름은 보이는 문구와 맞춘다. 실제 경로에서 키보드 초점과 복귀, 선택·비활성·대기·오류를 확인한다. 움직임은 위치나 상태 변화를 설명할 때 적절히 쓰고 동작 줄이기 설정을 따른다. |
| 좁은 화면 | 넓은 화면의 위계를 기준으로, 꼭 함께 봐야 할 근거를 가까이 유지한다. 표나 지도처럼 두 축이 필요한 곳만 그 영역의 스크롤을 검토한다. 주변 텍스트와 조작은 화면에 맞아야 하며, 내용이 잘리면 너비·줄바꿈·구성을 고친다. |

## 모션의 빈도와 중단을 확인한다

- 자주 반복하는 키보드 조작은 전환 없이 즉시 반응하는 안부터 본다. 모션을 남겨도 다음 입력이나 초점 이동을 전환 완료까지 기다리게 하지 않는다.
- 팝오버가 움직이며 열린다면 화면 중앙이 아니라 실제 트리거 쪽을 기준으로 삼는다. 화면 가장자리에서 팝오버 방향이 바뀌는 경우도 확인한다.
- 여는 도중 `Esc`로 닫거나 빠르게 다시 열었을 때 최신 입력이 즉시 반영되는지 확인한다. 닫힌 뒤에는 초점이 돌아와야 하고, 동작 줄이기에서도 같은 과업을 완료할 수 있어야 한다.

## 렌더를 보고 한 번 더 고친다

1. **전체 → 첫 화면 → 실제 크기의 핵심 영역.** 썸네일로 시선의 중심과 균형을 보고, 실제 크기로 본문·간격·줄바꿈·컨트롤을 확인한다. 맨 큰 영역과 가장 강한 색이 사용자의 목적을 돕는지 본다. 효과를 잠깐 걷어 내고도 우선순위가 보이는지 판단한다.
   첫 화면에서 바로 찾거나 처리하려는 서비스라면 실제 항목과 첫 조작이 보이는지 확인한다. 큰 도입부나 고정 영역이 이를 밀어내거나 덮으면 줄이고 재배치한다. 좁은 화면의 하단 조작 영역은 스크롤 전후에 항목, 차트, 키보드 초점을 가리지 않는지 본다.
2. **무엇이 화면을 상투적으로 만드는지 찾는다.** 서로 같은 카드 반복, 모든 항목의 배지, 습관적인 헤더 여백, 떠 있는 장식, 제목을 다시 말하는 부제가 발견되면 각 요소가 하는 일을 확인한다. 위계가 흐리면 크기와 간격을, 관계가 흩어졌으면 위치를 바꾼다. 한 요소를 덜어 보고 내용과 조작을 제자리에서 이해할 수 있으면 정리한다.
3. **실제 사용 경로를 따라간다.** 좁고 넓은 화면에서 같은 과업을 수행한다. 변경과 관련된 경우 긴 이름, 빈 결과, 실패, 키보드, 확대, 제품의 두 테마를 확인한다. 그래프와 색 표식에는 필요한 이름과 수치를 남긴다. 효과나 작은 수정 때문에 기능·포커스·가독성이 바뀌었는지 같은 조건에서 다시 본다.
4. **근거에 맞게 남긴다.** 시각적 위계는 캡처로, 클릭·입력·복구는 실제 조작으로, 대비나 리플로 적합성은 해당 기준과 실제 값으로 판단한다. 사용자가 실제로 빨라졌다는 판단에는 사용자 관찰이 필요하다.

대비·리플로 기준이 필요한 작업은 [W3C 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)와 [W3C 리플로](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)를 확인한다. 입력 오류와 서비스 장애의 구분은 [GOV.UK 오류 메시지](https://design-system.service.gov.uk/components/error-message/)의 관련 지침을 참고할 수 있다.
